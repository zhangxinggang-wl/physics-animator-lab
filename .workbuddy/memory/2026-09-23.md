### 本日踩到的两个新坑（已写入 MEMORY.md 与 SKILL.md）

- **`browser.close()` 在常驻 rAF + MathJax 的页面上不返回**，headless shell 会话卡死 → node 进程永不退出。
  首轮审计「跑了 9 分半零输出」，我一开始误判成页面/选择器问题。定位工具是 `probe_anim_stage.js`

### ⚠️ 抓到两个真实缺陷（都是 devicePixelRatio 惹的，dpr=1 时完全正常）

**症状**：单栏版首屏画布顶部横幅「过程1 小球下摆」只露左半截、右侧被裁；放大视图 HUD 整块不见了。
**根因**：框架 `resize()` 执行了 `ctx.setTransform(ratio,0,0,ratio,0,0)`（`ratio = devicePixelRatio`），
之后**所有绘制坐标按 CSS 像素解释**；而 `ctx.canvas.width/height` 是**设备像素**——
本例 dpr=2 时画布 1356×894，代码用 `(W - bw)/2` 居中 ⇒ 按 2 倍偏移画到画布外。
`FIG.processBanner`（模板）与本题 `drawHud`（生成器）都踩了这个坑。
**修法**（两处都改）：
```js
const r = ctx.canvas.getBoundingClientRect();
const Wp = (r && r.width)  ? r.width  : ctx.canvas.width;
const Hp = (r && r.height) ? r.height : ctx.canvas.height;
```
用 `getBoundingClientRect()` 而非全局 `W/H`，因为这两个函数可能被左栏题图画布复用
（`drawStaticGraph` 里临时把全局 `ctx` 指向题图画布，此时全局 `W/H` 是动画画布的尺寸、会取错）。
- 模板 `FIG.processBanner` 已修（**影响所有后续生成的题**，是模板级 bug）。
- `drawHud` 已在 `build_arc_cart.py` 内修好并重建完整版。
**验证**：t=0 的 HUD 区域非白像素 17,230 → 36,783（翻倍，说明 HUD 真的画进来了）；
末态 HUD 读数 θ=70.5°、h=0.100 m、当前=共速一起运动，与解析的「物块在 70.5° 处与小车共速」逐位一致。

1. **`起点` 标签被行驶中的车架扫到**：绿环固定在初始位置，而自行车**向右平移**，

2. **`Δs` 标签撞 θ(t) 弧**：`FIG.vec` 自动标签在末端 1.12 倍处，正好落在红色 θ 弧上。

3. **`s₂` 标签（最难，重做 9 次）**：绿矢量最长仅 80 px 且整段在车轮内部，四周被轮圈/辐条/

   - 矢长 **< 29 px（θ < 44°）时画布上不存在**「离障碍≥11px 且离矢量≤26px」的位置 ⇒ **无处可标**；

   放弃小角度标注是正确取舍——数据面板始终给出 s₂ 数值，信息不丢失。
