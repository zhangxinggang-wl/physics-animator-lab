## 任务：《用位移传感器测小车速度》教学动画

题源：人教版配套题【例 3】——A 盒（红外线 + 超声波发射器）装在匀速右行小车上，B 盒（红外线 + 超声波接收器）固定，
B 收到红外线开始计时、收到超声波停止计时，时间差为 t₁（声速 v₀，红外线传播时间忽略）。
**答案**：(1) $x_1 = v_0t_1$；(2) $\Delta x = x_2 - x_1 = v_0(t_2-t_1)$，$v = \dfrac{v_0(t_2-t_1)}{\Delta t}$。

产出：`2026-09-22_位移传感器测小车速度_教学动画.html`（2.19 MB，单文件自包含）。
新增脚本：`_build/build_sensor_cart.py`、`_build/audit_sensor.js`、`_build/shot_cols.js`、
`_build/shot_narrow.js`、`_build/probe_ir.js`。

## 本题设计要点

1. **双时间尺度时间轴**：声波飞行只有毫秒量级（t₁ = 5 ms），而两次发射间隔 Δt = 1.25 s，
   同一速率播放波前会一闪而过。故用分段线性映射 `SEGS`（动画秒 → 真实秒 τ）：
   声波飞行段慢放（0.9 s 演 5 ms）、小车前进段近 1:1，并在画面里**明确标注「声波飞行段为慢放」**，
   数据面板同时给出「演示时刻 t」和「真实时刻 τ」两个读数，保证既不糊弄也不失真。
2. **取一组自洽的示例值**：v₀ = 340 m/s、t₁ = 5.00 ms、t₂ = 7.50 ms → x₁ = 1.70 m、x₂ = 2.55 m、
   Δx = 0.85 m、Δt = 1.250 s → v = 0.680 m/s。两式互校（v = Δx/Δt 与 v = v₀(t₂−t₁)/Δt）一致。
3. **读数与解析逐项对齐**（关键）：末态数据面板必须严格读出 x₁ = 1.700 m、x₂ = 2.550 m、Δx = 0.850 m。
   最初把「A 到 B 的当前距离」直接显示，末态是 2.555 m（因为第二次声波飞行期间小车又走了 5 mm），
   与答案 2.550 冲突。改为**按「发射瞬间」取值**：$x_2 = x_1 + v\min(\tau,\Delta t)$，末态即 2.550/0.850。
4. **题图孪生锁定**：左栏题图 = `drawSceneBody(0)`，与原图一致（B 盒 + 支架 + 导线「连接到计算机」、
   A 车实线在 P、虚线残影在 Q、x₁/Δx/x₂ 尺寸线、P/Q 竖参考线、红外线红虚线、发射/接收红蓝圆点）。
   解题辅助 HUD（横幅 / 信息带 / 图例）统一放进 `if (t > 0.002)`。
5. **波前用真实圆形**：超声波是球面波，用「以发射点为圆心、半径 $v_0\tau$ 的圆弧（±26°）」表示，
   取发射点为圆心而不是跟随小车——这一点正是本题的物理要害（声波在介质中传播，与波源运动无关）。

## 踩坑与修正（本次新增，已同步 SKILL.md）

1. **画布竖向预算必须按 H 的比例来算（最重要）**：动画栏在 1280/1366/1600/1920 视口下，画布 CSS 宽只有
   **395 / 423 / 494 / 590 px**（`.col-animation{flex:1.3 1 340px}`），而画布高恒为 0.66×宽 → 最窄时只有 261 px 高。
   第一版把 HUD 信息带写成固定 110px 高，直接把世界场景的 x₂ 尺寸线压到了信息带里。
   正确做法：信息带取 `[0.115H, 0.39H]`，世界视图的 `ymax` 按「0.39H 对应世界高度」反算，
   所有 HUD 行位置写成 `b0 + bh * 系数`。四宽度实测均已无叠压。
2. **`note` / `basis` 走 `innerHTML`，不支持 Markdown**：写成 `**加粗**` 会在页面上**原样显示两个星号**。
   改用 `<b>…</b>`，并在生成器里加一行 `re.sub(r"\*\*(.+?)\*\*", r"<b>\1</b>", STEPS)` 防复发。
3. **HUD / 绘图函数必须放进 `GLOBALS`（顶层），不能追加在 `READOUTS` 之后**：`/*__READOUTS__*/` 位于
   `function readouts(t){ ... }` 的函数体内，把 `drawBanner/drawTimeBand/drawWave` 追加在那儿会被塞进
   `readouts` 内部 → 全局不可见 → 播放时 `ReferenceError: drawTimeBand is not defined`，
   而且 `loop()` 里 `render()` 抛错后 `requestAnimationFrame` 不再排期，**动画会直接卡死在 t=0**
   （门禁表现：`distinctFrames = 1`、`#next` 点不动）。生成器末尾加了「行首无缩进的顶层函数」探针自检。
4. **像素坐标短箭头不能用「压线白底标签」**：t₁ = 5 ms 对应的双箭头只有 ~26 px，而标签宽 ~55 px，
   白底会把箭头整条盖掉。改为 `pxArrow(..., below=true)` 把标签放到线下方；长箭头（Δt）仍用压线标签。
5. **波束边界虚线必须限长**：从发射点画到波前两端的长虚线会穿过尺寸线、台面，看起来像工程辅助线；
   封顶 `min(r, 0.42 m)` 只在发射点附近画一小段「定向波束」即可。
6. **图例折行方向**：按可用宽度自底向上折行时，`lines[0]` 落在最下面，读起来顺序是反的；
   改为 `y = H - 10 - (n - 1 - li) * 15`，自上而下即图例顺序。
7. **纵横比系数**：之前记的 `yrange ≈ 0.594·xrange` 是 443px 宽画布下的值；实测动画栏画布宽 395~590px 时
   该系数在 **0.585~0.613** 之间，取 **0.60** 最稳；本次把 0.615 改回 0.60（车轮/波前纵横比误差 < 2.5%）。

## 任务：《2024安徽14 弧轨道碰撞》教学动画

题源：2024·安徽·14（14 分）。水平面光滑，小车上表面＝粗糙水平轨道 + 光滑四分之一圆弧（相切于最低点）；
小球（m = 0.20 kg，L = 1.25 m）自水平位置释放 → 最低点与物块（M = 0.30 kg）弹性碰撞 →
物块沿轨道运动（s = 1.0 m，R = 0.15 m，g = 10 m/s²）。

**答案**：(1) T = 6 N；(2) v2' = 4 m/s；(3) 1/2 ≤ μ < 4/5。

产出：`2024安徽14_弧轨道碰撞_教学动画.html`（2.30 MB，单文件自包含，14 步解析）。
新增脚本：`_build/build_arc_cart.py`、`_build/audit_arc.js`、`_build/shot_zoom_arc.js`、
`_build/probe_ovf.js`、`_build/probe_fig.js`、`_build/list_tex.py`。

### 物理建模（第三问是关键）
- 上界：物块要能进圆弧 ⇒ v_in² > 0 ⇒ μ < v2'²/(2gs) = 16/20 = 0.8。
- 下界：「上升阶段不脱离」⇒ 须在到达顶端（θ = 90°）前与小车共速。
  由动量守恒 + 机械能守恒消去 V 得
  u² = (v_in²/4 − gR(1−cosθ)) / (1/2 − cos²θ/4)，
  取临界 u²(90°) = 0 ⇒ v_in² = 4gR = 6 ⇒ μ = 0.5。
- 演示值 μ = 0.60 ⇒ v_in = 2 m/s，共速角 θ ≈ 70.53°，h = R(1−cos70.53°) ≈ 0.100 m，共速 V = 1.00 m/s。

### 本次踩坑（重要）
1. **`\frac` 触发 MathJax「Math input error」**（headless Chromium 下必然复现，页面出现黄色错误块）。
   `\tfrac` **不**触发；`\begin{aligned}` 也触发。本题 14 步公式全部改用 `\tfrac`、所有多行环境改单行
   后 `assistiveMerrors = 0`。这是本模板的高频坑，已写入 MEMORY.md。
2. **`document.body.innerText` 里的 "Math input error" 不能当判据**：模板注释自身就含这串字，
   且 MathJax 会为每个公式生成 `MJX-ASSISTIVE-MML`（内含 `<merror>`）。判据应取
   `document.querySelectorAll('mjx-container.mjx-error').length` 与可见 merror 数量。
3. **审计脚本等 MathJax 必须用「稳定检测」**：`mjx-container` 数量连续 6 次采样不变且零 error 才放行；
   否则 139+ 公式只排完一半就截图 ⇒ 假阴性（`mjx=0`、`steps=0`、画布空白）。
4. **滑块必须写刻度值**：`<input type=range min=0 max=1000>`，`t = value/1000*duration`；
   审计里写秒数会让 t 恒为极小值（画面永远停在起始帧）。
5. **填充区作用域**：`__GLOBALS__` 在顶层；`__SETUP__`/`__DRAWFRAME__`/`__READOUTS__` 在对应函数体内，**只能放语句**。
   本次把 `SLIDE_END_DX`（引用 `GEO.spix`）误放在 `GEO` 声明之前 ⇒ `Cannot access 'GEO' before initialization`，
   **整页脚本中断**，表现是**题干为空、题图不存在、只剩一块空白动画画布**（`probe_fig.js` 才定位到）。
   经验：`const` 存在 TDZ；凡是引用 `GEO` 的派生常量，一律写在 `GEO` 之后。
6. **孪生锁定题图会暴露所有几何 bug**：题图 = `drawSceneBody(0)`，所以任何「悬点/圆弧/物块坐标不随小车平移」
   的不一致都会在题图上放大显示。本题小车在下摆阶段被细线水平拉力反冲，改为让 `xPivot`、`arcSurface`、
   `R` 虚线、物块圆弧坐标**全部叠加 `st.cartDx`** 才自洽。
7. **圆弧最低点必须锚定「水平轨道右端 + cartDx」**（而不是轨道左端 + 固定 spix），
   否则滑行段与圆弧段衔接处会出现 0.43 世界单位的跳变。
8. **公式横向溢出**：解析栏在 1280px 下最紧。对策＝「精简 + 版式微调」双管齐下：
   ① 把数值代入链、中间推导移入 `note`；② 长分式改 `A/B` 定义式；
   ③ 追加 `<style id="tune-width">`（`.step` 内边距 12→9px、`.tex` 左右 padding 归零、
   `mjx-container[display=true] svg{max-width:100%}`、解析栏 `flex` 2→2.05）。
   最终 1280/1366/1600/1920 四宽度 `texOverflow = 0`。
9. **中文 stdout 经 PowerShell 抓取必乱码**（如 `鐢诲竷绋冲畾灏哄 = 640x420`），
   但页面本身没问题——看数值结论不要被乱码误导。
