## 一、字符串注入层（本项目最隐蔽的一类坑）

产物 HTML 是用 Python 脚本把 LaTeX / JS 代码**注入模板**生成的。注入这一层出错，
症状统一表现为「页面看着正常，但公式渲染成 `Math input error`」，极易误判为公式写错。

### 1.1 `re.sub` 的替换串会吞反斜杠 ⚠⚠ 头号坑

**症状**：某个 `mjx-container` 渲染失败，其 SVG 宽度异常窄（`width="16ex"`），
assistive-MML 下出现 `<merror>`。逐条单测 `STEPS.tex` 全部干净 —— 说明公式本身没错。

**根因**：`re.sub(pattern, 替换串, out)` 会把替换串里的 `\b` `\d` `\t` `\f` `\Delta`
当成**反向引用 / 转义**处理，反斜杠被直接吞掉：

| 想注入 | 实际进入 JS | MathJax 收到 |
|---|---|---|
| `O_1=\big(` | `O_1=(` | `big` 命令丢失 |
| `\Delta t` | `Delta t` | 变成三个字母 |
| `\dfrac{1}{2}` | `dfrac{1}{2}` | — |

**修法（强制）**：**所有 `re.sub` 的替换串一律用 `lambda m: payload` 包一层**。

```python
# ✅ 正确：lambda 返回，payload 原样插入
out = _re.sub(r'const STEPS = \[[\s\S]*?\n\];', lambda m: steps_js.rstrip('\n'), out, count=1)

# ❌ 错误：裸字符串当替换串，反斜杠被吞
out = _re.sub(r'const STEPS = \[[\s\S]*?\n\];', steps_js, out, count=1)
```

### 1.2 Python `%r` / `repr()` 不能转义反斜杠

```python
repr('a\\Db')   # => "'a\\Db'"  ← 反斜杠仍未转义，JS 会把 \D 当转义序列
```
**修法**：写进 JS 源码的字符串字面量**统一走 `json.dumps(ensure_ascii=False)`**，
它与 JS 字面量语法完全兼容。

### 1.3 产物级硬门禁（务必加进生成器尾部）

比 Playwright 更早定位问题，且能直接指出是注入层坏了：

```python
_bad = []
for _m in _re.finditer(r'tex: "((?:[^"\\]|\\.)*)"', _out):
    _t = _m.group(1)
    if _re.search(r'(?<!\\)\\[A-Za-z]', _t):   # 单反斜杠 + 字母 = 危险
        _bad.append(_t[:70])
if _bad:
    for _b in _bad: print('BAD  单反斜杠: %s' % _b)
    raise SystemExit('反斜杠被吞：re.sub 替换串未用 lambda 包一层')
```

### 1.4 裸尖括号会破坏 HTML 结构

`\(z=0<z_0\)` 里的裸 `<` 被浏览器当标签起始 ⇒ 定界符配对失败 ⇒ 裸定界符门禁 FAIL。
**修法**：一律写 `\lt` / `\gt`。

### 1.5 `\mathrm{}` 不能放中文

`\mathrm{合}` ⇒ MathJax 报错。**修法**：用 `\text{合}`（`\mathrm` 只收字母）。

### 1.6 note 字段走 `innerHTML`，不解析 Markdown

模板用 `innerHTML` 插入 note，**`**加粗**` 会原样显示**。**修法**：直接写 `<b>加粗</b>`。

### 1.7 `ctx.fillText` 的坐标是屏幕像素，不是世界坐标

```js
// ❌ 把世界坐标当屏幕像素 ⇒ 文字落到画布 (0.8px, 0.3px) 处被裁，
//    表现为「画布顶端一条被裁掉的残字」，常被误判为上一帧残影
ctx.fillText('结论…', 0.80, 0.30);

// ✅ 凡按世界坐标定位的文字（含结论句、说明句）必须先过 W2S
ctx.fillText('结论…', W2S(0.86, 0.30)[0], W2S(0.86, 0.30)[1]);
```
> 诊断线索：**残字固定出现在画布左上角** ⇒ 一定是坐标体系用错，不是重影问题。

### 1.8 路径数组必须多 push 一个哨兵

分段几何的 `OFF`/`IDX` 类数组，只 push 每段起点（长度 = 段数）时，
最后一段取 `OFF[i+1]` 为 `undefined` ⇒ 插值返回 `NaN` ⇒ **该段绘制整体静默消失**。

```python
# 症状：红色「已走轨迹」在 t≥某时刻后整段不见了，只剩灰色虚线
# 修法（构造循环外补哨兵）：
PATH_OFF.push(FULL_PATH.length);
```

## 二、画布尺寸与 dpr

### 2.1 拿画布尺寸必须用 CSS 像素

```js
// ❌ canvas.width/height 是设备像素。框架已 setTransform(ratio,…)，
//    后续绘制坐标全按 CSS 像素解释 ⇒ 居中/靠右算出来会放大 2 倍、画到画布外
const W = ctx.canvas.width;

// ✅
const r = ctx.canvas.getBoundingClientRect();
const w = r.width, h = r.height;
```
> 症状：**只在 dpr=2 时出现**，表现为「横幅只露左半截」「HUD 整块消失」。
> **新写 HUD/横幅前先 `grep ctx.canvas.width`。**
> 另外不能用全局 `W/H`：`drawStaticGraph` 会临时改 `ctx`。

### 2.2 模板 `clearBg()` 在 dpr>1 时清不干净

模板原实现按 `canvas.width/height`（设备像素）清屏，而 `resize` 已 `setTransform(ratio,…)`
⇒ 顶部约 `H/ratio` 的条带永远残留上一帧。**修法**（就地覆盖模板函数）：

```js
function clearBgCss(){
  ctx.save();
  ctx.setTransform(1, 0, 0, 1, 0, 0);              // ① 复位后按设备像素全清
  ctx.clearRect(0, 0, ctx.canvas.width, ctx.canvas.height);
  ctx.restore();
  const _r = ctx.canvas.getBoundingClientRect();  // ② 再按 CSS 像素铺白
  const w = (_r && _r.width) ? _r.width : ctx.canvas.width;
  const h = (_r && _r.height) ? _r.height : ctx.canvas.height;
  ctx.clearRect(0, 0, w, h);
  ctx.fillStyle = '#fff'; ctx.fillRect(0, 0, w, h);
}
```
> ⚠ **模板修了不会自动回填历史 HTML**：改完 `assets/template.html`
> 必须跑 `scripts/patch_processbanner.py` 扫全部已产出文件。

### 2.3 画布顶部有「禁区」

`processBanner` 固定占 y=8~37 px，HUD 从 `42*k` 起、高 `(14+15n)*k`。
三栏下 H≈321、PAD=36 ⇒ **sy≈108 px 即 HUD 下沿**，世界坐标 `y > 0.50` 的标注必被遮。

**判据**：先反算 sy 像素位置，再放标签 —— **别凭感觉试**。

### 2.4 HUD 不能写死像素高度

三栏下画布宽仅 395~590 px、高 0.66×宽，必须按比例定位再反算 `VIEW.ymax`。

### 2.5 底部图例 ≥4 项必须多行

单行时 `iw = lw/n` 不足 ⇒ 文字互相重叠。**4 项改 2 列 × 2 行**，
字号 ≥10 px，标记与文字偏移按项宽重算。**图例自底向上要倒序。**

### 2.6 比例尺：等比例尺判据

`yrange/xrange` 须等于该画布**实际内宽**下的理想纵比 `(0.66·W内−72)/(W内−72)`。
三栏取 0.60 最稳；单栏恒 680 px ⇒ 0.6196。
**判据**：`W2S` 描点的弧会不会变椭圆。

## 三、作用域与 TDZ

| 坑 | 症状 | 修法 |
|---|---|---|
| 绘图/HUD 函数放进 `readouts` 体内 | 播放时 `ReferenceError`，rAF 不再排期 ⇒ **动画卡死 t=0**（`distinctFrames=1`） | 绘图函数必须放 `GLOBALS` |
| 派生常量写在 `GEO` 之前 | `Cannot access 'GEO' before initialization` ⇒ 整页中断（题干空白 + 无题图 + 空白画布，**易误判成模板问题**） | 引用 `GEO` 的常量写在 `GEO` 之后 |
| 非 `__GLOBALS__` 区放声明 | 语法错误 | 那三区在**函数体内**，只能放语句 |
| **JS 里用了未声明的裸标识符**（如直接写 `PI` 而不是 `PAR.PI`） | 页面能加载、`syntax_check` 三段全 OK，但 `distinctFrames=1`（动画卡死 t=0）**且左栏孪生题图整块空白**（题图 = `drawSceneBody(0)`，同一处报错）。**最隐蔽的一类** | 在生成器加**未声明标识符门禁**：剥掉注释/双引号/单引号/模板字符串后扫大写常量，与 `PAR`/`GEO`/函数名比对 |
| **判据常量声明在首次使用之后**（TDZ） | 同上：`const NEAR_TAN = …` 写在用它的 `drawParticle(...)` 之后 ⇒ 每帧 `ReferenceError` | 派生判据一律在使用点**之前**声明 |
| `BANNERS` 等常量**声明两次**（GLOBALS_JS 里一份、生成器又单独拼一份） | `Identifier 'BANNERS' has already been declared`，`syntax_check` 只有第 3 段 FAIL | 只在 GLOBALS_JS 里声明一次；生成器**不要再生成第二份** |

> **未声明标识符门禁的两个要点**（照抄即可用）：
> ① 扫描范围**只能取注入的四段 JS**（`GLOBALS_JS + HELPERS_JS + DRAWFRAME_JS + READOUTS_JS`）。
>    扫整个产物（2 MB+）会被 CSS 色值 `#E8E8E8`、LaTeX 宏、中文散文里的 `CH`/`CP`/`OM`
>    淹没成噪音；
> ② 剥离顺序必须是 **块注释 → 行注释 → 双引号 → 单引号 → 模板字符串**。
>    漏掉单引号时，HUD 文案 `'…= CH'` 里的 `CH` 会被误判成未声明标识符。

> `__CANVAS_STATIC__` 孪生题图 = `drawSceneBody(0)`，
> 任何「元素没跟参考系平移」的 bug 都会暴露 —— 善用。
> 反过来，**任何让 `drawSceneBody` 抛错的东西，会同时抹掉动画与左栏题图** ——
> 这两处同时为空白时，先怀疑 JS 运行期错误，而不是模板或样式。

## 四、标注定位（本项目最耗时的一类）

### 4.0 中文标注绝不能用斜体 serif（新增，2026-10-16）

`ctx.font = 'italic bold 13px serif'` 里的汉字会渲染成**伪斜体** —— 中文没有真正的
斜体字形，浏览器只能做几何倾斜，看起来「字歪了」，像渲染错误。

**修法**：`leadLabel` / `dimLine` 里按是否含 CJK 切换字体：

```js
function hasCJK(s){ return /[\u4e00-\u9fa5]/.test(s || ''); }
const cjk = hasCJK(txt);
ctx.font = ((opts.italic === false || cjk) ? '' : 'italic ')
         + 'bold ' + (opts.size || 12.5) + 'px ' + (cjk ? 'sans-serif' : 'serif');
```

纯字母/数字（`r`、`R`、`30°`）仍用 serif 斜体，符合原题画法。

### 4.1 运动体会扫过固定标注 ⇒ 必须暴力搜索安全区

先用 `scripts/probe_start_label.py` 算「全程离所有障碍 ≥N px」的区域，**不要凭感觉试**。
若邻域内无解 ⇒ 唯一解是**引线标注**（文字放空白区 + 细点线连回，颜色淡、短划，
避免像工程尺寸线）。

> ⚠ **搜索出来的「最优解」未必可用**（圆形磁场区域题实测）：
> 脚本按「离锚点近」排序给出的第一候选贴住了 x 轴（裕度仅 4.5px）；
> 改成按**裕度从大到小**排序才得到可用点（裕度 54px）。
> 且即便裕度够大，位置仍可能与**另一条引线标注交叉**。
> ⇒ 排序键要用 `(-round(margin,1), dist)`，且**拿到结果后必须看一眼它与
> 同屏其他引线是否交叉**，必要时改为「按阶段显示」而不是全程常驻
> （见 4.5 的 `r` 标注：阶段②③隐藏，只在粒子静止的阶段①④出现）。

### 4.2 静态文字与运动粒子必冲突

粒子每次跨界面都会经过固定标注的锚点。**加隐藏判据**比反复挪位置可靠：

```js
const nearIface = (st.phase !== 'q3') && (Math.abs(st.z - PAR.z0) < 0.16);
drawKeyLabels(st, nearIface);   // 此判据下隐藏会被压住的引线标注，结论交由 HUD 承载
```

### 4.3 声波/光束的「定向锥角虚线」——已致缺陷两次
从波源向波前两端拉锥角虚线，参数（波前半径）变大后会变成**斜穿场景的长虚线**，
看起来像多余的工程辅助线。

**结论：新题一律不画锥角**，改用「主波前 + 内侧渐淡残影弧」，
方向用弧顶的短小 `→`/`←` 箭头表示。
若确需方向提示，锥长必须与波前绑定：`lb = Math.min(r*0.55, 0.30)`
（写 `Math.min(r, 0.42)` 会随物体跑远拉成长斜线）。

### 4.4 圆弧张角必须与尺寸标注带联合约束

弧顶点高度 `$y_0 + r_{max}\sin\theta$` **必须小于最下方那条尺寸线的 y**。
否则弧线横穿尺寸标注、压住字母/数值（3× 特写才看得出）。

**双保险**：① `half` 收到 10°；② 对弧加硬裁剪 `yTop = W2S(0, Y_DIM1-0.02)`。

### 4.5 其他高频细节

- **极短矢量（<30 px）** 放不下行内标签 ⇒ **抬门限：短到读不出对应关系就不标**（面板已有数值）。
- **两个标签各自扫场** ⇒ 定位 A 时要同时检查与 B 的距离。
- **两条尺寸线共用端点** ⇒ 标签必须一个放线上方、一个放下方，垂直错开。
- **法线方向按屏幕坐标系推导**：世界方向 `(ux,uy)` ⇒ 世界坐标下的屏幕右法线 `(-uy, ux)`。用反了会镜像压住另一条线。
- **旋转矢量标签**：① 说明文字下铺白底让位；② 偏移按朝向取符号外推。
- **短箭头**不用压线白底标签（会盖掉箭头），放线下方。
- **`FIG.ground/wall` 的 `gap`/`hatchLen` 是世界长度**。**画墙+磁铁先画磁铁再画墙。**
- **圆弧段必须与物块用同一锚点**（否则衔接跳变）。**边界虚线要限长。**
- **多条引线标注必须分处不同「高度带」**（新增，2026-10-16）：阶段④同时给出
  2~3 条结论时，若都挂在右侧同一高度带（y≈0.3~0.6），一眼就是叠字。
  修法：结论文字按出现顺序分置 y≈0.86 / 0.55 / 0.24 等不同带，引线起点也各取不同点。
- **尺寸线标签的偏移量要比「线宽 + 字号一半」更大**：`dimLine` 的 `off` 默认 12~13px 时，
  标签基线会压在箭头线上（`R` 字被蓝色箭头穿身）。
  ⇒ 标签挂在尺寸线**下方**时用 `off: 18`；挂上方时 `off` 同样要 ≥16。
- **静态符号布点要考虑尺寸线标签的存在**：画在圆内的 ⊗/× 磁场符号，
  若正好落在尺寸线标签（标签挂在尺寸线下方 18px 处）会被压住。
  ⇒ 磁场符号布点后**必须逐个检查是否与各尺寸线标签的距离 ≥16px**。
- **粒子停在高位点时，速度矢量要按阶段缩短**：末态粒子停在 P（y=1）、
  矢量指向左上，长度仍用 0.20 时箭尖会冲出画布上沿并压住过程横幅
  （阶段①~③ 看不出来，只有末帧暴露）。
  修法 `(st.stage === 'geo') ? 0.13 : 0.20`，或按「箭尖世界坐标 ≤ ymax − 0.06」反解长度。
- **`FIG.text` 的 y 参数是世界坐标**（内部过 W2S），但顶部横幅占 sy 8~37、
  底部图例占 sy 271~313 —— 标注的 y 必须先反算 sy 再定，**别凭感觉**。
- **`FIG.particle` 标签在球下方**，易与矢量/地面重叠。**`FIG.pendulum` 的 angle 向 +x 为正。**
- **竖排文字盒**：先量盒内净高像素，再定 `字号 ≤ 净高/(字数+1)`、
  步进 ≤ 字号×1.1，末字留 6 px 下边距 —— 否则末字被盒底截断
  （5 字「粒子发生器」用 13 px 必被切）。

## 五、公式渲染判据

### 5.1 `\frac` 不是禁忌，真凶是多行环境

实测 `\frac` 完全正常（`mjx-error=0`）；真正炸的是**多行环境 `\begin{aligned}`**。

### 5.2 `merror` 计数不可靠

```js
// ❌ 会匹配 assistive-MML 中正常公式自带的 <merror>，误判
document.querySelectorAll('merror').length

// ✅ 可靠判据
document.querySelectorAll('mjx-container.mjx-error, mjx-container[data-mjx-error]').length
```

### 5.3 MathJax 稳定检测

固定 `waitForTimeout(3500)` 在 1600 px + dpr2 下会假阴性。
**改为**：连续 6 次采样 `mjx-container` 数量不变且零 error 才算稳定。

### 5.4 横向溢出

解析栏在 1280 px 最紧 ⇒ 精简公式或追加 `<style id="tune-width">` 压 padding / 控宽。

## 六、探测与审计脚本陷阱

| 坑 | 症状 | 修法 |
|---|---|---|
| `browser.close()` 挂死 | 审计无输出直接结束 | `Promise.race([close, 6s])` 后**显式 `process.exit`**；每个 await 套超时；日志重定向到文件，不要 `| head` |

| 探针搜可能出现在注释里的串 | 假 FOUND / 假 MISSING | 先剥 JS 注释（块 + 行）再搜 |
| Python 里写含 `%` 的 CSS 片段 | `max-width:100%` 触发格式化报错 | 用 `.replace()`，不要 `%` 格式化 |
| 超长 `python -c` 内联 | 中文括号触发 "File name too long" | 写真实 `.py` 文件 |
| 用旧 `syntax_check.js` | Windows 必抛 `spawnSync … EBUSY` ⇒ 三段全报 `SYNTAX FAIL` 的**假阴性** | 用 `scripts/syntax_check.js`（`vm.Script` 同进程解析） |

## 八、复检铁律

**同一道题重建 / 重跑，也必须重走 3× 人工看图**，不能因为「上次过门禁」跳过。

真实案例：某题重建时，波束边界斜虚线在 `t ≈ 3.0 s`（第二次发射刚发生、波前很薄）
横穿场景压住 `v` 箭头 —— 上次抽样的 7 个时刻**恰好没覆盖这段**所以漏检。

**抽样时刻必须覆盖「每个物理阶段的起始处」**，不能只取各阶段中点与末态。

### 8.1 `shot_zoom.js` 只截 t=0 ⇒ 运动中的缺陷一律看不见

`shot_zoom.js` 结尾把滑块强制拨回 0 再截图，**只适合查静态版面**。
「粒子压住标注」「弧线横穿尺寸线」这类缺陷**只在运动中出现**，
必须另写按时刻抽样的脚本（见 `examples/generators/` 同级的 `scripts_shot_stages.js`）：
对每个物理阶段的**起始时刻**各截一张，dpr=3。

⚠ **截图前必须先 `scrollIntoView` 把画布滚回视口，再按 `getBoundingClientRect` 裁剪**：

```js
await page.evaluate(() => document.getElementById('cv')
  .scrollIntoView({ block: 'center', behavior: 'instant' }));
const rect = await page.evaluate(() => { /* 返回 cv 的 getBoundingClientRect */ });
await page.screenshot({ path, clip: rect });     // ✅
// await cv.screenshot({ path });               // ❌ 会把上方标题栏一起拍进来
```

**原因**：模板 `updatePanel` 里有 `stepEls[i].scrollIntoView({block:"nearest"})`，
每次切步骤都会把页面滚到解析栏；此时元素截图按视口坐标取框，拍到的是**画布上方那块页面**。
症状是截图里莫名多出「动画演示」标题和一个被截掉一半的横幅。

### 8.2 细窄空间里不要叠多条标注 —— 每阶段只画该问需要的

板间缝、极板间隙这类区域往往只有 0.5 个世界单位高（约 35px）。
往里塞 3 条尺寸线 + 3 个标注，标注间距（0.16 单位 ≈ 11px）小于字号（11.5px）**必然叠字**。

**修法：按阶段裁剪标注** —— 第(1)(2)问只画题设里那条，第(3)问只画该问求的那两条。
信息量不减，画面却永远只有 1~2 条标注。

### 8.3 浅色底轨（完整轨迹）必须随阶段变

固定画「全部 N 轮递推」的底轨时，**低轮次那一问的底轨与实际红色轨迹完全不同**，
屏幕上出现一堆看不懂的灰圈，还会让读者以为轨迹分叉。
**修法**：`buildFullPath(q)` 按问取参数；每问只画该问电压下的完整路径。

### 8.5 单栏抽取：`shot_stages.js` 的时长是硬编码的

`scripts/shot_stages.js` 里 `s.value = Math.round(v / 35 * 1000)` —— **35 是某道题的时长**。
换题必须改成本题的 `SIM.duration`，否则**所有截图都停在 t=0**，
看起来「画面完全正常」，实际一个运动帧都没拍到（浪费一轮复核）。

改的时候注意变量名是 `s` 不是 `slider`：
`sed 's|slider.value|…|'` **匹配不上**，会静默不替换 ⇒ 用 `s.value` 或直接写脚本。
另外 `shot_stages.js` 里 `require('./chrome')` 是**同目录相对引用** ——
脚本复制到 `_build/` 后必须把 `chrome.js` 一起复制过去，否则报 MODULE_NOT_FOUND。

### 8.6 单栏画布放大后，会暴露三栏时看不见的叠字

单栏 680px vs 三栏 486px，放大 1.4 倍，**像素间距小于字号的关系会突然成立**。
实例：粒子的 `v` 标签挂在速度矢量中点上方，粒子抵达 P 点时与 `P` 点标签叠字 ——
三栏 486px 下勉强不叠，单栏 680px 下明显叠在一起。

⇒ **单栏必须重走一遍人工看图**（铁律的延伸），不能因为「三栏已看过」跳过。
修法优先用**判据隐藏**而非挪位置：`showV = Math.hypot(st.x - px, st.y - py) > 0.17`
（此时速度方向信息已由角标与数据面板承载，不丢信息）。

### 8.4 「相切点 / 交点」是全图最容易叠字的位置

一个相切点通常同时压着：挡板直线、角度弧、末端点标记、圆弧、粒子本体与两个矢量标签。
单一手段（移动任意一个）都救不了，**必须三管齐下**：

1. **引线标注** —— 文字统一挪到远处空旷区，用细短虚线连回交点；
2. **判据隐藏** —— 粒子进入交点邻域时隐藏它的 `v`/`+q` 标签，信息交给 HUD 与数据面板；
3. **阶段性隐藏** —— 交代几何用的角标（如 `37°`）只在第一问出现，
   后面正是交点区，再放必挤。
### 8.7 `FIG.coord(..., {labels: []})` 会被判为「要画标签」⇒ 轴标签重影

模板 `coord` 内部是 `if (opts.labels){ ...默认画 'x' 和 'y'... }`，
而 JS 中 **`[]` 是真值** ⇒ 传空数组照样会画出一套默认轴标签。
若生成器自己又用 `FIG.text` 画了 `'x'`/`'y'`，三栏时两者恰好重叠看不出来，
**单栏（画布 680px）就分成两个 `x`、两个 `y`**（单栏 3× 特写实测）。

⇒ 想禁用模板的标签必须传 `labels: null`，不能传 `[]`。
一般化铁律：**凡是「传空集合 = 关闭某功能」的模板 API，都要先确认它是
`if (x)` 还是 `if (x && x.length)`**；空数组在 `if (x)` 里是真值。

### 8.8 白底结论卡片：宽度要按「最宽一行文字的像素宽」反推，不能只按世界宽度

卡片框是 `W2S(x0..x1)`，但里面文字是**像素字号**，二者不是同一套尺度。
初版把卡片放在 `x∈[0.36, 4.90]`（世界宽 4.54），三行文字最长约 340px，
而该世界宽度在 494px 画布上只有 245px ⇒ 整段溢出右缘被裁。

⇒ 卡片 x 范围要**一直铺到该高度上的全部空白带**（本题 `x∈[-3.90, 4.95]`，
左侧 `y≈-2.5` 一带本来完全空白），而不是「看起来够用的那一段」。
另配三条：① 卡片高度按行数 × 行距反推（0.68 世界单位 ≈ 3 行）；② y 轴 / 尺寸线
在卡片顶上方就截断（`yAxisBot: -2.05`），否则会插进白卡片里；③ 同步更新
`FIELD_AVOID` 的卡片避让带，否则磁场符号会落在卡片上。

### 8.9 「同一页面切换参数」的三条作用域铁律（把常量改成运行时重建）

做 `n = 2 / 3` 这类**同页切换**时，几何不能留在 Python 里算死成常量，
必须改成 `buildForN(n)` 在 JS 运行时重建。由此暴露三条作用域坑：

1. **`__SETUP__` 是函数体，不是顶层作用域** ——
   模板是 `function setup(){ /*__SETUP__*/ }`。在里面写 `function applyN(){}`，
   页面按钮回调与 Playwright 的 `page.evaluate(()=>applyN(3))` **都拿不到**，
   报 `ReferenceError: applyN is not defined`。
   ⇒ 切换函数必须放 **GLOBALS 区**（顶层），`__SETUP__` 只留一行注释。
2. **初始化调用必须早于模板的 `resize()`** ——
   模板启动顺序是 `resize() → STAGES=buildStages() → … → setup() → render()`，
   而 `resize()` **内部就会 `render()` 补一帧**。
   ⇒ `buildForN(N_LIST[0])` 要写在 GLOBALS 区**顶层末尾**（紧跟注入点），
   不能等 `setup()`；否则首次渲染时 `PAR/SEGS` 全是 `undefined`。
3. **被 buildForN 调用的辅助函数必须声明在它之前** ——
   `segPos()` / `pathIndexOf()` 原来定义在几何块之后，改成运行时重建后
   `buildForN` 内部就会调它们。JS 函数声明会 hoist，但 `let PAR/SEGS/KEY/T` 这类
   **`let` 不会** ⇒ `buildForN` 里赋值 + 别处读取的变量（`SEG_T`）
   必须 `let` 在 `buildForN` **之前**，否则 TDZ。

另附一条通用推论：**切换参数后 `STAGES` 必须同步重算**。
`STAGES` 由 `STEPS[].t0/t1` 推导，而段数变了（5→7）时间轴边界也变了，
不重算的话「上一步/下一步」会跳到错误时刻。

### 8.10 探针里的 `toFixed` 会把断言打成假 FAIL

`+PAR.r2.toFixed(6)` ⇒ `1.333333`，与 `4/3` 差 3e-7 ⇒ `Math.abs(a-b)<1e-9` 判 FAIL，
但物理其实完全正确（截图与页面都正常）。
⇒ 探针里**不要**对要断言的物理量做 `toFixed`；确需压缩输出时用 `JSON.stringify`
打印，断言另走原始值 + 相对容差 `near(a,b) = |a-b| < 1e-9·max(1,|b|)`。

## 9. 2026-11-04 · 2011·福建·22 正交 E×B 场摆线（新增 7 条）

### 9.1 取景：世界窗口铺满画布 ⇒ 顶部被 HUD 压住、底部空一大片

**症状**（门禁全 PASS，但人工看图很明显）：
- 磁场上排的 × 符号、y 轴箭头、B 标签被 HUD 白框切掉一半；
- 画布底部 1/4 是纯白（内容只到 y≈−5.6，世界窗口却延伸到 y=−14.3）。

**根因**：`ensureView()` 把世界窗口反解成「铺满整个画布」：

```js
VIEW.xmin = xc - (cssW/2 - PAD)/sPx;  VIEW.xmax = xc + (cssW/2 - PAD)/sPx;
VIEW.ymin = yc - (ycPx - PAD)/sPx;     VIEW.ymax = yc + (cssH - PAD - ycPx)/sPx;
```

于是 `ymax` 对应屏幕 `PAD`（画布顶），而 HUD 压在 42~94 px ⇒ 内容上沿必然钻到 HUD 底下。

**修法（正解）**：内容只能落在「**绘图带**」里——HUD 下沿 ~ 图例上沿。

```js
function band(){
  const k = fk();                                   /* 字号缩放系数，必须乘！ */
  const hudBot    = (LAYER.hudTop + 48) * k + 6;   /* HUD 框下沿（2 行文字） */
  const legendTop = H - (LAYER.legendBot + LAYER.legendH) * k;
  const top = Math.max(LAYER.bandTop, hudBot);
  const bot = Math.min(H - PAD, Math.max(top + 80, legendTop));
  return { top: top, bot: bot, h: bot - top };
}
function ensureView(){
  const bd = band();
  const sPx = Math.min(innerW / bw, bd.h / bh);     /* 同一 px/世界单位，不拉伸 */
  const ycPx = bd.top + bd.h / 2;                   /* 内容中心该落在带中心 */
  VIEW.xmin = xc - innerW / (2*sPx);
  VIEW.xmax = xc + innerW / (2*sPx);
  VIEW.ymin = yc - (cssH - PAD - ycPx) / sPx;
  VIEW.ymax = VIEW.ymin + (cssH - 2*PAD) / sPx;     /* ⇒ W2S 的 x/y 比例尺相等 */
  scale = sPx;
}
```

⚠ **两条铁律**：
1. `band()` 的上下沿**都要乘 `fk()`**。HUD 用 `LAYER.hudTop*k` 画，单栏 680px 版 `k=1.42`
   ⇒ HUD 高 68px、下沿到 127px；不乘 `fk()` 就会盖住 96px 处的带顶。
2. `WBOX`（内容盒）必须把**轴箭头 + 标签字高 + 场符号点阵 + 尺寸线**全包进去，
   否则标签被画布上/下沿裁掉。本题：`{x0:-3.6, x1:36.4, y0:-7.0, y1:12.6}`。

### 9.2 ⚠ 世界坐标原语与像素坐标原语混用 ⇒ 整幅图飞出画布

**症状**：丙图（y–t）只有两条尺寸箭头还在，坐标轴、曲线、全部文字都没了；
**门禁照样全 PASS**（只查「画布非白像素>0」，尺寸箭头就够了）。

**根因**：`drawYT()` 里 `x0/x1/yb/yt/gx/gy` 全是**像素**，却传进了世界坐标原语
`seg / wt / polyline / arrowW`——这些内部都走 `W2S()` ⇒ 像素被当世界坐标再变换一次，
坐标飞出画布。

**修法**：像素空间另配一整套原语，两套**绝不混用**：

```js
function segPx(x1,y1,x2,y2,color,lw,dash){ /* 直接 ctx.moveTo/lineTo */ }
function arrowPx(x1,y1,x2,y2,color,lw,head){ /* 像素版箭头 */ }
function polyPx(pts,color,lw,dash){ /* pts 是像素点列 */ }
function wtPx(px,py,str,opts){ /* 像素版文字 */ }
function dotPx(px,py,r,color){ /* 像素版圆点 */ }
function wtBoxPx(px,py,str,opts){ /* 像素版白底文字（把身后曲线挖空） */ }
```

⇒ **凡是「按画布像素布局」的图（y–t、a–v、能量图）一律用 *Px 原语。**

### 9.3 交点上的小标记被线切碎

`y=h` 交点用 `ringW(x, y, 0.42, ...)`（半径 4 px）标红圈 ⇒ 灰色轨迹从圈心穿过，
肉眼只看到「一小点红」，读不出是圈。
⇒ **先画白底圆盘挖空，再画环**：

```js
dotW(hx, H_MM, 6.0, '#ffffff');   /* 圆盘把轨迹线挖掉 */
ringW(hx, H_MM, 6.0, '#dc2626', 2.4);
```

（注意：白底盘会顺带切断穿过该点的**虚线**——这正好是「标记遮断参考线」的自然观感。）

### 9.4 初速箭头与瞬时速度箭头同起点同向 ⇒ 叠成一团

原点处黑 v₀ 箭头（初速度）与红瞬时速度箭头同起点、同方向 ⇒ 画面上是一团双头箭头。
⇒ 用阈值二选一显示，交接点几乎无感：

```js
const AT_START = (st.th < 0.30);           /* 起始瞬间显示 v₀ */
if (AT_START) arrowW(0.15, 0, 2.9, 0, '#111827', 1.6, 5.5);
if (!AT_START) arrowW(粒子, 粒子+速度*k, ...);  /* 之后由瞬时速度箭头接管 */
```

标签放在**轴线下方**（本题轨迹恒在 y ≥ 0 ⇒ 永不与运动粒子相撞）。

### 9.5 横幅序号必须与 STEPS / HUD 序号一致

横幅按物理阶段拆成了 6 条、编号 ①②①③④⑤，而解析栏与 HUD 是 ①②③④
⇒ 同一屏出现「横幅说③、解析栏说②」，学生以为错位。
⇒ **一个步骤可以有多条横幅，但序号必须与 STEPS 一致**：

```
① 受力分析：电场力向下、洛伦兹力垂直速度
① 受力分析：洛伦兹力只改方向，电场力做负功
① 受力分析：粒子沿摆线轨迹前进（E×B 漂移）
② 第(1)问：只有电场力做功
③ 第(2)问Ⅰ：空间周期 s = 2πmE/(qB²)
④ 第(2)问Ⅱ：y 方向做简谐运动
```

### 9.6 尺寸线必须落在所有曲线之下

乙图（不同 v₀ 的曲线族）里最低那条曲线（k=0.25）最低点 y=−3.91，
而「s」尺寸线原放在 −3.4 ⇒ 曲线穿过尺寸线并把「s」标签压掉。
⇒ 尺寸线改到 −5.9；且乙图里 **y 轴不再向下延伸**（否则与尺寸线的竖直虚线叠在一起）。
另：`WBOX.y0` 要跟着放大到 −7.0。

### 9.7 截图脚本的时长是写死的

`scripts/shot_stages.js` 里 `s.value = Math.round(v / 35 * 1000)` —— **35 秒是某道题的 duration**。
本题 `SIM.duration = 19` ⇒ 照抄会抽出一堆 t≈0 的帧，还以为动画没动。
⇒ 按 `SIM.duration` 换算：`s.value = Math.round(t / SIM.duration * 1000)`。

### 9.8 原题图常常是「示意图」

原图甲的「拱高/拱宽」实测 ≈1.29，而真实 trochoid 的 `2A/s = 1/π ≈ 0.318`。
⇒ 动画**按真实参数方程**画（等比例尺），并在解析的 note 里明写「原图甲为示意图」。
反推办法：原图拱顶是**尖点** ⇒ 对应 `v₀ = 2E/B` 的尖点特例（本题即取此值，A = s/(2π)）。

### 9.9 图例样例必须与画面一致

乙图的 x 轴是**实线**，图例却画了虚线样例 ⇒ 新增 `axsolid` 类型画实线，
`axis` 类型保留虚线（丙图的「中线 y=A」确实是虚线）。

## 12. 2026-11-05 · 2015·江苏·15 质谱仪（新增 7 条）

### 12.1 ★★ 半圆的「真实时长」≠「几何角」——最隐蔽的物理 bug

**症状**：离子在磁场中只走完弧的左上段（约 50°）就停下/落点，永远走不满半圆；
**而所有门禁全 PASS**（画布非白像素由弧线贡献，零报错，distinctFrames 正常）。

**根因**：归一化后 m = 9/32 ⇒ 半圆**真实时长** th = πm/(qB) = 0.884（**弧度值 0.884**）；
但半圆的**几何角**是 **π = 3.1416 弧度**。写成

```js
const th = I.th * u;          // ❌ th 是时间量，不是角度
st.theta = Math.PI + th;      // ⇒ 只转过 0.884 rad ≈ 50.6°
```

**正解**：

```js
const th = Math.PI * u;       // ✅ 几何转角：0 → π
st.theta = Math.PI + th;      // θ 自 π 增至 2π（下半圆）
// I.th 只用于「真实时间 → 屏幕时间」的换算，不进角度公式
```

⇒ **凡是「角度 = f(时长)」的动画，必须分清「几何量」与「时间量」两个 π 的来源。**
自检：断言 `|P − 圆心| ≡ R` 且终点 `θ = 2π` 时落在 `2R` 处。

### 12.2 扫描参数时，屏幕时间分配要按真实时间比例

随手给「加速段 0.74 / 弧段 0.20」⇒ 加速:半圆真实比例明明是 ≈1:5，
离子却长时间停在加速区，「扫描落点」的主线被稀释。
⇒ 屏幕占比按**真实时长比例**给（本例 17% : 71% : 12%）。

### 12.3 窄条上的两个标签并排必叠字 ⇒ 分置高度带 + 向外偏移

MQ 段宽 2/3 L、QN 段宽 1/3 L，两条标签并排必然相撞。
**解法不是缩字号**，而是：MQ 标签放条**下方**一档、QN 标签放条**右侧外侧**空白，
两者处在**不同高度带** ⇒ 互不干扰。

### 12.4 同一页多段并列 ⇒ 序号用单符号（①②③）放块内部

块宽仅 40~48 px 时，「第1次」三个汉字（≈33 px + 标签框内边距）必然叠字。
改用单个 15 px 的 ①②③ 放进块**内部**中央 ⇒ 绰绰有余；
「第几次」的文字说明移到图例或独立行。

### 12.5 下标「₀」要与主字符分开画，偏移量由 `measureText` 量出

写死 `+7px` 会随字号/字体漂移（本次 U₀ 的 0 一度跑到 U 的**左下方**）。
正解：先 `measureText('U')` 量宽，再 `fillText('0', up[0] + wU/2 + 1.0*fk(), up[1] + 1.4*fk())`。

### 12.6 数值探针的判据本身也会写错

「点是否在圆上」应比较 **|P − 圆心| 与 R 之差**：
```js
const d = Math.abs(Math.hypot(st.x - st.R, st.y) - st.R);   // ✅
const d = Math.hypot(st.x - st.R, st.y);                      // ❌ 得到「误差 = R」的假 FAIL
```

### 12.7 「原落点 / 映射后落点」用上下双标尺，中间夹刻度尺

引导虚线只走在两排之间的空白带；**斜段穿过的水平位置必须逐次验算**
（本例交点 x = 1.79~1.95，恰在标签范围 0.35~1.65 之外 ⇒ 不冲突）。
标签一律分置：上排说明在上、下排说明在下、结论另起一档。

## 13. 弹簧 / 斜面姿态 / 标注层级（2022 全国乙 25 实测）

### 13.1 弹簧锚点必须钉在物块上，不能跟着走远的物块拉伸

`x1 = max(xB, xA - l0); x2 = xA` 这种写法**在分离后**会把弹簧整根搬到 A 左侧悬空
（B 已追不上，弹簧却仍长 l0 且左端脱离 B）。实测 4.25–11.5 s 段左端离 B 达 0.5–3.3 m。
正解：**左端恒为 `xB`，右端 = `xB + min(l0, max(0, xA - xB))`** —— 压缩时右端追随 A，
分离后自动回到原长并留在 B 上；A 上坡期间弹簧照样画（挂在 B 右侧），不要 `if (onRamp) return`。

### 13.2 方块上/下斜面的姿态：用「后下角」单参数驱动，别分支插值

「水平姿态 ↔ 斜面姿态」各自算再 smoothstep 插值，会在坡脚穿模：实测右下角切入坡体 0.204 m，
坡面线直接划过 A 的身体；再加"沿法向外移"补丁还会因**符号写反**把 A 整个推进坡里。
正解（一个公式覆盖平地/坡脚/坡上/坡顶，且恒相切）：
```js
const xRear = onRamp ? xs + Math.max(0, xi - wA/2) * cosT : xA;  // 后下角 x
const aRear = xs - xRear;                                        // >0 还在坡脚左侧
let phi, rx, ry;
if (aRear > 1e-9){                                               // 平地侧：绕后角抬起
  phi = clamp(ang0 - Math.asin(clamp(aRear*sinT/wA, -1, 1)), 0, ang0);
  rx = xRear; ry = 0;
} else { phi = ang0; rx = xRear; ry = (xRear - xs) * (sinT/cosT); }
center = (rx, ry) + R(phi)·(wA/2, hA/2);
```
`xi = wA/2` 时两分支给出**同一个位姿** ⇒ 跨坡脚零跳变；`aRear > wA` 时 φ 自动为 0（平地）。

### 13.3 坡顶要额外延伸一段坡面承托 A 的整个底面

A 的最高点让**底边中点**落在坡顶，则半个底边（0.17 m）已越过坡顶；延伸段若只有 0.24 m
（沿坡）仍不够，缩略图上就是"A 悬在坡顶外的空中"。取 `EX ≥ wA + 0.10`（本例 0.44）。

### 13.4 标注（h / θ）先画、物块后画，让物块盖住标注线

`drawRampMarks` 排在 `drawBlocks` 之后时，h 的顶部虚线引线与 θ 弧会**横穿 A 内部**；
交换顺序后由 A 的实心填充遮挡，视觉上"A 压住标注"远比"标注压住 A"自然。

### 13.5 「悬空」的判据要用像素/数值，不能靠缩略图

3× 截图缩到 1080 宽后，2–3 px 的描边间隙会被读成"明显悬空/明显贴合"，来回误判三四轮。
判定用两条硬指标：①角点到坡面直线的有符号距离 `-(x-xs)sinT + y cosT`（应 ≈0）；
②对蓝色描边做**最小外接旋转矩形**（枚举 0.25° 步长）看角度是否 = 坡角、边长是否 = wA·scale。

## 14. 时间轴可达性 / 白盒宽度预算（2022 江苏 15 实测）

### 14.1 「只在 f=1 成立」的状态 = 死代码 ⇒ 驻留段设计
症状：出射环 + 出射标注（leadLabel）在成片里永远看不到；截图怎么都拍不到。
根因：`exited = tPhys >= T−ε` 只在 step 末点成立，而滑杆步进（1000 档）
与播放都会跳过这个零测度瞬间——相位在 t≥t1 已切到下一步。
修法：run 模式改「前 88% 运动 + 后 12% 驻留在出射点」：`g = Math.min(1, f/0.88)`，
tPhys = tMax·g。驻留期 exited=true、粒子停在出射点，标注有 ~0.5s 展示窗。

### 14.2 驻留帧的瞬时速度箭头会穿过出射标注、盖住顶角字母
修法：`if (sp > 0.15 && !st.exited)` 才画速度箭头——出射环 + 白盒标注已足够表达。

### 14.3 leadLabel 白盒的宽度预算：先把 scale 算对
症状：标注本身没问题，但 A/D/O′ 等顶角字母被**整块擦掉**（wtBox 白底）。
根因一：标注文字太长（中英混排 12~15 字符 ≈ 170 css px，在高受限取景下
scale≈13.9 css/世界 ⇒ 文字宽 ≈ 12 世界单位，横穿整个装置顶带）。
根因二：目测像素比例时把 dpr/裁剪倍率搞错 ⇒ 修法是**写 10 行像素簇审计**：
对期望字形位置（如 D 的 image x 区间）统计深色像素数，被擦 = 0。
修法：结论性文字交给横幅/HUD，画布标注只留最短判据（如 `x≈7.6d＜8d（✗）`），
并逐个微调 tx 使白盒与两侧字形都留 ≥10px 间隙；改完必须重拍放大验证。

### 14.4 探针比对要先剥反斜杠归一
症状：FOUND/MISSING 探针大面积误报 MISSING。
根因：tex 注入走 json.dumps，产物里是 `\\dfrac`（双反斜杠），探针写的是单反斜杠。
修法：`needle.replace('\\','') in out.replace('\\','')` 归一后再比对。

### 14.5 复制骨架后先核对「用到的函数是否都有定义」
症状：audit 报 `ReferenceError: fk is not defined`、画布全白、distinctFrames=1。
根因：HELPERS 段漏搬 `fk()`。修法：构建器尾部加「未声明大写标识符门禁」之外，
再人工核对 DRAWFRAME/HELPERS 用到的全部小写函数名（fk/W2S/seg/wt/…）都有定义。
