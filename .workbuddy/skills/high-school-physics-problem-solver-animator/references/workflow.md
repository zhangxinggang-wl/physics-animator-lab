### 端到端工作流

#### 第 1 步：审题与获取题目（图片题强制先做 OCR）

> **图片题强制流程**：用户上传的是**试题图片**时，第一件事是把图片里的**文字识别进文件**（见下「OCR 文字入文件」），再谈解析与动画。

- **若用户给的是图片**：
  1. **OCR 文字入文件（强制）**：先用 OCR 把图片中的全部文字识别出来，并**逐字写入** `PROBLEM`（`title` / `given` / `asks`）。可选手段（按优先级）：
     - **(a) 本地离线 OCR 脚本**：运行 `_build/ocr/run_ocr.py`（基于 RapidOCR `rapidocr_onnxruntime`，输出带行框坐标的文字，便于还原排版）；若该依赖未安装，先 `pip install rapidocr-onnxruntime onnxruntime` 再运行。
     - **(b) OCR 技能**：调用 `yescan-ocr-universal` 技能做文字识别。
     - **(c) Read 视觉转录（兜底）**：直接用 Read 工具读取图片（WorkBuddy 支持读图），由视觉能力逐行转录文字。
  2. **OCR 易错字复核（强制）**：印刷体常被误识为 `l↔1`、`O↔0`、`I↔1`、`α↔a`、`×↔x`、`—↔-`、`·↔.` 等。识别后必须逐字与原图核对订正，**禁止把错识字当成原题**。
  3. **题干原文一致性**：OCR 得到的文字写入 `PROBLEM` 后，必须与原图**逐字一致**（一字不增、一字不减，不擅自改写标点/加题号外标题）——严禁把 OCR 噪声带入最终交付。公式原文（如 `v0=2m/s`）也随文字一起识别进来，后续在第 5 步统一改写为标准 LaTeX（见「公式排版规范」）。
  4. **图形另走重绘流程**：图片中的图形（线条图形）**不靠 OCR**，按本技能「题图处理」与「图形与图元重绘强制条款 · 线条图形专项」用 `FIG.*`/自定义 `ctx` **重新绘制成完全相同的线条图形**。
- **若用户给的是文字**：直接解析，跳过 OCR。
- 明确记录：① 研究对象与参考系；② 已知量（含单位）；③ 所求量；④ 是否忽略某些因素的条件。
- 任何看不清或缺失的条件，**先向用户确认**，不要自行假设后当成已知。

#### 第 2 步：领域判定、知识点分类与物理建模

- 先判定题目所属领域（力学 / 电磁学 / 热学 / 光学 / 原理物理），再对照该领域参考手册第 1 节分类索引，确定具体知识点。
- **加载参考手册**：按领域读取对应文件（路径相对于本技能所在目录）：
  | 领域       | 参考手册                                        |
  | -------- | ------------------------------------------- |
  | 力学       | `references/mechanics_reference.md`         |
  | 电磁学      | `references/electromagnetism_reference.md`  |
  | 热学       | `references/thermodynamics_reference.md`    |
  | 光学       | `references/optics_reference.md`            |
  | 机械振动与机械波 | `references/oscillation_waves_reference.md` |
  | 原理物理     | `references/principles_reference.md`        |
  > 通用 LaTeX 规范（分数/根号/上下标/希腊字母/定界符）统一见 `mechanics_reference.md` 第 7 节；各专业手册第 7 节只补充该领域专属符号，两者务必同时遵守。
- 建立坐标系与符号约定（参考手册第 3 节），在草稿列出所用定律与公式，把相关公式、易错点、自检清单带入上下文。
- **必读第 8 节**：对应领域手册的第 8 节「典型题型正解库」列出了该领域标准解题范式与已验证的正解示例。动手推导前先读一遍，并**优先套用其中的标准范式与公式形式**，这是保证解析正确的主要依据。

#### 第 3 步：推导解析（强制物理依据 + 自检）

逐步骤推导，每一步必须：

1. 写明**所用定律/公式名称**（如「由法拉第电磁感应定律」「由热力学第一定律」）；
2. 写出公式，再代入数值；
3. 说明该定律**为何适用**（适用条件）。
     
   推导完成后，逐条执行对应领域参考手册第 5 节**正确性自检清单**：

- 量纲一致、符号约定一致、定律适用条件成立、极限/特殊情形合理、数值数量级合理、结论闭环回到所问。
- 任一项不满足且无法当场核实 → 在对应步骤 `flag:true` 并写 `basis:"…待核实"`，说明疑点；**绝不允许编造结果**。
- 若对公式/常数拿不准，用 WebSearch 核对权威来源后再写。

#### 第 4 步：设计动画映射

- 依据对应领域参考手册第 6 节，把解题过程映射为可视化要素。各领域的典型映射：
  - 力学：位置/轨迹、速度矢量（可分解 vx/vy）、受力/加速度矢量、能量条形图、动量对比、临界状态高亮；
  - 电磁学：电场线/等势面、带电粒子在磁场中的圆周轨道与速度矢量、磁通量变化与感应电流、p–V/电流波形；
  - 热学：p–V 过程曲线与做功面积、气体分子热运动、循环效率演示；
  - 光学：入射/折射/反射光线与法线、透镜成像光路、干涉条纹；
  - 原理物理：矢量合成（平行四边形）、分量分解、量纲关系、误差传递。
- 确定动画总时间 `SIM.duration`：
  - 对于宏观过程（落体、碰撞、电路暂态等），`SIM.duration` 必须等于解析中的物理过程时长；
  - 对于**微观/极快过程**（如带电粒子在磁场中的回旋周期常为微秒量级），直接按真实时长无法观察。此时**保持空间几何严格由真实公式驱动**（如轨道半径 `r = mv/(qB)`），仅对时间轴做可视化放慢，并在题面/解析中明确标注「动画已放慢以便观察，真实周期见解析」。这种做法不破坏「动画即解析的可视化」的本质。
- 设定世界坐标范围 `VIEW`，保证场景完整可见；确定矢量显示缩放因子。
- **动画必须与解析逐步骤对应、清晰且真实（最高优先级）**：动画不是「示意图」，而是解析过程的**忠实可视化**。（1）**逐步骤对应**：`STEPS` 中每一步的 `t0~t1` 必须精确对应动画里该步骤的物理状态；用同一个 `stateAt(t)` 同时驱动画面（`drawFrame`）与数据面板（`readouts`），从机制上杜绝「画面一套数、面板另一套数」。（2）**真实可信**：位移/速度/受力/能量全部由**解析所用的同一套公式与参数**实时计算，保持真实比例与真实数量级，绝不为了好看而夸张、扭曲或编造轨迹；微观极快过程仅放慢时间轴、不改空间几何（见前文约定）。（3）**清晰**：关键状态（最高点、落地瞬间、碰撞/接触瞬间、脱离轨道、进入/离开磁场、换路时刻）用高亮或 `FIG.processBanner` 过程横幅明示，轨迹与矢量不杂乱，学生一眼能看懂「现在演到解析哪一步、为什么」。

#### 第 5 步：生成 HTML 交付物

基于模板 `assets/template.html` 生成，只填充下列 6 个区域，框架代码保持不变：

1. **`PROBLEM`**：标题、已知条件；**若题目含图，必须填 `images` 字段**（详见下方「题图处理」）；**若题目多问，必须填 `asks` 数组**，使每一问在原题区独立成行；**若为选择题，必须把 A/B/C/D 四项全部录入 `options` 数组**（详见下方「选择题选项录入（强制）」），四项缺一不可。**注意**：题干文字必须与原题逐字一致（详见下方「题干原文一致性」），**禁止**擅自加题号之外的标题、改写标点、加入"（单选）"等原题没有的标记；选项应放在 `asks` 之外并按原题版式单独渲染（紧贴题图下方），避免被「所求」标题和蓝色卡片样式包裹而改变外观。
2. **`STEPS`**（每条：`q / title / tex(LaTeX，模板自动以 \[...\] 渲染；每问最后一条即自动标记为「答　」前缀并红色高亮显示) / note(文字说明，其中公式须用 \(...\) 行内 LaTeX) / basis(物理依据) / t0 / t1`，不确定则 `flag:true`）。
   - **`title` 里不要再写「答　」前缀（强制）**：模板 `renderSteps` 会自动给**每一问的最后一个步骤**加上红色「答　」前缀并高亮（`.step.answer`）。若 title 里又自带「答　…」，页面会渲染出**左右相邻的两个红「答」**。
   - **末步（答）title 不要重复放结论公式（强制）**：`title` 写简短中文要点即可，如 `"（4）折射率"`、`"A 被敲击后获得的初速度"`、`"B 被敲击后获得的初速度"`；**不要写 `"\(v_{A}\)"` 之类的红色结论公式**——答案步骤的下方（`.tex`，黑色）会自动显示结论式，红色标题里再放一遍同一符号会出现「红色字母符号与下方黑色字母符号重复」的问题。结论若含公式由 `.tex` 统一承担即可。
   - **`q`**：该步骤属于第几问（1 开始）。**题目有多问时必填**，模板会自动把解析按 `q` 分组，每一问独立成块（蓝色标题），学生可逐问查看。
   - **`q-h`（每问蓝色标题）里不要再保留公式字母符号（强制）**：`q-h` 在视觉上是「这一问要回答什么」的总标题，写在 `.qblock .q-h` 蓝色条上。如果直接用 `PROBLEM.asks[g.key-1]` 原文（其中含 `\(v_{A}\)`、`\(a_{B}\)`、`\(a'\!_{B}\)` 等），经 MathJax 渲染后会在蓝色条上以**白色斜体+上下标**显示这些字母——而同一组符号会再次出现在下方 `.step .tex` 的**黑色公式**里，造成「红/蓝色条上的白色字母符号与下方黑色字母符号重复」。处理方法：`renderSteps` 在写 `.q-h` 时，对 `PROBLEM.asks[g.key-1]` 做一次 `replace(/\\\(([^\\)]*)\\\)/g, "")` 去掉所有 `\(...\)` 包裹的公式段（只保留中文描述部分）；左侧 `asks` 列表（`.asks li`）仍保留原文与公式——那里没有重复问题。模板与所有示例页均已按此实现：`.q-h` 的 `textContent` 是剥掉公式后的纯中文标题。
       
     **`t0` / `t1` 为该步骤对应的动画时间区间（秒），必填**——动画播放到该区间时，中间栏对应步骤卡片自动高亮，数据面板同步显示该步骤文字。区间划分要让**关键数据出现的时刻落在该步骤区间内部**（例如「求最大高度」这一步的区间必须包含到达最高点的时刻，不要恰好卡在边界）。
3. `VIEW` 与 `SIM.duration`；
4. `setup()`（预计算轨迹、常量）；
5. `drawFrame(t)`（用 `W2S` 转屏幕坐标，调用 `drawArrow/drawPoint/drawCircle/drawLine/drawText/drawAxes` 绘制）；
6. **`readouts(t)`（实时数据，必填）**：返回 `[名称, 数值字符串, 单位]` 数组，显示在右栏「数据面板」。
     
   **必须让 `readouts(t)` 与 `drawFrame(t)` 共用同一组状态函数**（推荐抽一个 `stateAt(t)` 供二者调用），这样面板数值与画面必然一致，不可能出现「画面一套数、面板另一套数」。
     
   数值项建议包含：时间、当前阶段、关键运动学量（位置/速度/加速度）、关键动力学量（力/能量），以及解析中算出的**最终结论值**。

> **题干原文一致性（强制，最高优先级）**：左栏「试题原题」区域的题干文字必须与试题**逐字一致**——原文有多少字、什么标点、什么顺序，左栏就呈现多少字、什么标点、什么顺序；**严禁**：
>
> - 改写措辞、合并/拆分句子、补字/删字；
> - 添加原题没有的标记（如「（单选）」「（多选）」「（共 N 问）」等）；
> - 添加题号之外的额外标题（题号若原题有则保留，没有则不要自拟）；
> - 把选项合并进题干长句再写到 `asks`；选择题的 A/B/C/D 四项必须完整录入 `PROBLEM.options`（一项都不可省略、不可篡改），不得塞进 `asks`、不得并入题干（参见第 1 项说明）。
>     
>   哪怕只是"为了让语句更通顺"也不行——原题是什么样就什么样，**一字不增、一字不减**。

> **题图处理（强制 · 完美重绘）**：只要题目原文中出现「如图所示」「见图」或题目明确给出图片，就必须把图片嵌入 HTML 的题面区。禁止用文字描述替代图片；图片位置应贴近题干的对应位置（通常在题干之后、所求/选项之前）。
>   
> **图形位置无关（强制）**：无论图形在试题图片的**哪个位置**——左上角、右下角、跨栏、夹在文字之间，还是与多道题同处一页——都必须把图形**完整、完美地**提取并重绘/嵌入，**不得因图形偏居一角、被文字包围或跨页而省略、裁切或只取局部**。
>   
> **题图必须「与试题原图完全相同」**——按下面三种方式任选其一实现：
>
> - **方式 ①（优先）**：嵌入题目原图本身。用 `assets/img2b64.js` 把用户提供的题图转成 data URI 填入 `PROBLEM.images[].src`，由 `<img>` 原样显示，确保与试题中的图形**完全相同**。
> - **方式 ②（Canvas 2D 像素级重绘 · 与动画孪生锁定，禁用 SVG viewBox）**：按原题图几何，用 **JavaScript Canvas 2D**（`beginPath()` / `moveTo()` / `lineTo()` / `arc()` / `fillText()` 等）以**固定像素尺寸（如 800×600）硬编码**重新绘制，填入左栏 `<canvas class="fig-canvas">`，**严禁使用 SVG 的 `viewBox` 通用缩放**（避免坐标漂移）。该静态图形与右栏动画**复用同一套绘制函数 `drawStaticGraph()` / `drawSceneBody()`**（孪生锁定，见下「## 图形重绘工作流」），其几何、线型、长度比例、角度、填充样式、字母标注必须与原题图形**完全相同**——原题有什么就画什么，**严禁**自行增加原题没有的辅助元素（法线虚线、延长光线段、坐标轴、未标注红点、网格填充替代实心填充等）。
> - **生成式题目（无上传原图）强制重绘 · Canvas 孪生锁定**：当用户未上传图片、而是由本技能直接生成题目（如 `generate_problem.py` 这类生成器）时，**必须**用方式 ② 现画一张 Canvas 题图——且与右栏动画**共用同一套 `drawSceneBody()` / 世界坐标**（`VIEW`、各物块/墙/地/弹簧/摆坐标），**不得留空、不得只放文字描述、不得用 SVG viewBox 另绘**。实现上：把 `PROBLEM.images[].src` 置为特殊标记 `__CANVAS_STATIC__`，页面加载时由动画的 `drawStaticGraph(canvas)` 在左栏 `<canvas class="fig-canvas">` 上以 `t=0` 绘制一次（即「孪生锁定」的静态端）。这张题图就是「试题中重新绘制的图形」，右栏动画每一时刻暂停态都必须与它逐线吻合（见「题图→动画图形严格一致」与「图形与图元重绘强制条款」）。即：用户看到的左栏题图 ≡ 右栏动画第 0 帧，二者同源、零偏差、像素级重合。
> - **方式 ③（从大图/截图裁剪）**：当上传的是含图的大图（整页试卷、题面截图、多题同页照片）时，先用图像裁剪把图形所在区域单独切出（图形无论位于原图何处都完整切出，不缺角、不裁半），再走方式 ① 嵌入或方式 ② 重绘。裁剪可用 `assets/img2b64.js` 的裁剪参数或外部图像工具完成；切出后务必人工核对图形四边完整。
>     
>   **题图显示尺寸（强制）**：题图不要铺满整列，应**适当缩小并居中**。模板已把 `.fig` 设为 `margin:12px auto; width:max-content; max-width:100%;`、`.fig img` 设为 `width:auto; height:auto; max-width:230px; max-height:168px; margin:0 auto`，左栏渲染后约 230×120 px，比整列宽更紧凑，与下方内容之间留出视觉缓冲。如需对个别题图微调，仅在该 HTML 的 `<style>` 里覆写即可，不要把模板回退到 `width:100%` 那种铺满写法。
>

> - **变力做功**：用动能定理、能量守恒、图像面积或分段求和，不用 `W=\int F\,dx`。
> - 若严格解（如考虑安培力导致减速）与高中近似结果有差异，**以高中近似结果为答案**，并在 `note` 中注明「若严格考虑××，精确值约××，二者接近」。
> - `note` 中允许出现「图像面积」「平均值」「抛物线弓形」等高中表述，但 **`tex` 字段不得出现 `\int`**。

### 动画物理引擎生成规范（强制）

> 用户明确要求：当根据试题图形重绘并生成动画演示时，**动画必须基于物理方程逐帧数值积分**生成高保真、可交互的物理情景动画；风格为**干净的矢量图**，带**坐标轴**与**速度/受力矢量箭头**。以下四条核心原则、场景映射、执行流程、两项绘制细节均为强制，与「## 图形重绘工作流」「## 题图→动画图形严格一致」同源，生成时一并满足。

#### 一、核心原则 (Core Principles)

1. **物理正确性优先**：动画的每一帧必须**由物理公式计算得出**（如 $x=x_0+v_0t+\tfrac12at^2$，简谐 $x=A\cos(\omega t+\phi)$），**严禁用线性插值（Lerp）模拟物理运动**，除非该运动本身就是匀速直线运动（此时逐帧位置本就线性）。凡是加速度、速度随时间变化的情形，必须以解析方程驱动 `stateAt(t)`，再据此绘制，不得用「起止点之间按比例插值」冒充物理轨迹。
2. **矢量可视化**：所有动力学场景**必须绘制受力分析图**（重力、弹力、摩擦力、向心力等）与**速度 / 加速度矢量箭头**；箭头**长度按统一比例尺缩放**以反映大小变化（如某矢量缩放系数 `k = 比例px/单位`，则绘制长度 `=|矢量|×k`），并在箭头旁标注实时大小或符号。
3. **交互与控制**：生成文件**必须包含**「开始/暂停」「下一步」「上一步」「重置」按钮（模板已内置，勿删、勿改样式）。「上一步／下一步」按 `STEPS` 的 `t0` 锚点跳转并暂停，「重置」回到 `t=0` 并清空高亮。
4. **画布与坐标**：使用 Canvas 绘制，并建立**合适的坐标系**——原点通常在画布中心或左下角，画布边缘显示**坐标轴箭头与刻度尺**（调用 `FIG.coord` / `drawAxes`）。坐标系需覆盖完整场景（`VIEW` 设定合理范围），使位移、角度、轨迹一目了然。

#### 二、物理场景映射逻辑 (Mapping Logic)

依据对应领域参考手册第 6 节与下列映射编写动画 JS：

- **力学 (Mechanics)**
  - 直线运动：`x += v*dt`、`v += a*dt`（数值积分）。
  - 斜面：分解重力 `a = g(\sin\theta - \mu\cos\theta)`，检测是否到达底部/顶部。
  - 抛体运动：水平匀速、竖直匀加（或斜抛匀减）；用**虚线轨迹点**绘制运动路径。
  - 圆周运动：极坐标或参数方程 `x = R\cos(\omega t+\phi_0)`、`y = R\sin(\omega t+\phi_0)`；**必须绘制向心加速度矢量（指向圆心）**。
  - 竖直圆周：用能量守恒求速度随角度变化 `v(\theta)=\sqrt{v_0^{2}+2gR(\cos\theta_0-\cos\theta)}`。
  - 简谐运动（弹簧振子）：`x = A\cos(\omega t+\phi)`，或基于胡克定律 `F=-kx` 做**数值积分（Verlet / RK4 积分器，确保能量守恒、防止振幅衰减）**。
- **碰撞 (Collision)**
  - 弹性碰撞：动量守恒与机械能守恒联立求解末速度；二维碰撞沿**法线方向分解动量**。
  - 完全非弹性碰撞：动量守恒求解共同速度，计算内能损失并**显示热量条**。
- **电磁学 (Electromagnetism)**
  - 带电粒子在磁场中：利用洛伦兹力 `F = q(\mathbf{v}\times\mathbf{B})` 更新速度；螺旋运动分解为「平行磁场的匀速运动」+「垂直磁场的匀速圆周运动」。
  - 变压器 / 交变电流：绘制正弦波形 `e = E_{\max}\sin(\omega t)`；线圈转动结合 2D 侧视图展示切割磁感线过程。
  - 电容器充放电：绘制指数增长/衰减曲线 `Q(t)=C\varepsilon(1-e^{-t/RC})` 或 `Q(t)=Q_0e^{-t/RC}`。
- **光学 (Optics)**
  - 反射 / 折射：严格遵循斯涅尔定律 `n_1\sin\theta_1=n_2\sin\theta_2`；入射角改变时反射角与折射角**同步即时更新**。
  - 干涉 / 衍射：用波程差公式 `\Delta = d\sin\theta` 或单缝衍射公式计算明暗条纹位置；光强分布用余弦平方或 `sinc` 函数模拟。

#### 三、执行流程

1. **分析需求**：确定用户要演示的具体物理场景（如「带阻力的抛体运动」「竖直圆周临界速度」）。
2. **确定参数**：列出影响该过程的所有变量（质量、阻力系数、初速度、角度、磁场、电容等）。
3. **构建代码**：编写包含上述物理逻辑的 HTML——抽出一个 `stateAt(t)` 同时驱动 `drawFrame(t)` 与 `readouts(t)`，从机制上保证画面与数据面板一致。
4. **自检**：回复前确认动画中物体运动符合物理直觉（自由落体越来越快；圆周运动绳拉力随位置变化；简谐振幅不衰减），并确认无 `Math input error`、无 Lerp 冒充物理轨迹。

#### 四、两项绘制细节（强制）

- **矢量箭头（drawArrow）**：代码中必须提供 `drawArrow` 函数，所有矢量（速度、加速度、力）都用**带箭头的线段**表示。当矢量大小**接近零**时，箭头应**自动淡出或消失**，避免画面杂乱。
- **轨迹追踪**：对抛体运动、圆周运动、振动，建议开启「**轨迹追踪**」功能，用**浅灰色虚线**绘制物体过去某段时间（或过去一个周期）的路径，便于观察运动规律。

#### 第 6 步：呈现与说明

- 用 `present_files` 打开生成的 HTML，供用户在浏览器/预览面板查看。
- 在回复中简要说明：题目领域与知识点、关键结论（数值+单位）、动画如何对应解析、以及任何 `flag` 待核实项。

### 矢量/符号标注的定位方法（强制：先建模，再动手）

> **核心教训**：标注叠字是本项目最高频、最耗时的可见缺陷，而且**自动化门禁完全查不出**
> （画布非白像素、零报错、四宽度零溢出全过）。**唯一可靠的验收方式是 3× 画布特写人工看图**，
> 且必须在**多个时刻**看——只看末态必漏（标签常是「某两个角度之间」才撞上）。

**动手前先做三件事，不要凭感觉挪坐标：**

1. **判断标注对象会不会移动**。若几何体本身在平移/转动（行驶的自行车、摆动的杆），
   则**固定的世界坐标迟早会被扫过**。写个几十行的纯 Python 暴力搜索脚本，
   逐时刻算出「离所有障碍 ≥N px」的区域，直接看结论。参考 `_build/probe_start_label.py`。
2. **量出标签的占位尺寸**：中文两字标签约 **26×13 px**（字号 13）。任何「间距 < 13 px」
   的所谓可行解都是假的——字会压线。
3. **检查标签之间会不会相遇**。给 A 定位时要同时盯住 B（B 也可能在扫场）。
   自行车题 `Δs`（沿法线外推）与 `s₂`（贴矢量尖端）在 θ=100°~150° 曾仅距 21~26 px，
   肉眼糊成一团 ⇒ 把偏移 0.22 加到 0.42 才拉开到 ≥35.6 px。

**三条结论性规则（踩过坑总结）：**

- **极短矢量（< 30 px）根本放不下行内标签**——四周不是箭头就是轮圈/相邻线。
  正确做法是**抬显示门限**：矢量短到读不出对应关系时**干脆不显示该标签**
  （数据面板始终给出数值，信息不丢失）。自行车题 `s₂` 门限抬到 29 px（θ ≥ 44° 才显示）。
- **若邻域内确实无解 ⇒ 用引线标注**，不要硬挤。文字放永久空白区，
  用**细点线**（`[2,3]`）连回目标，颜色取淡（避免像工程尺寸线）。
  自行车题 `起点` 标签即如此：绿环 75 px 邻域内无解，干净区在 268 px 外。
- **法线方向必须按屏幕坐标系推导**：世界方向 `u=(ux,uy)` 的「屏幕右法线」在世界坐标里是
  `(wnx,wny) = (−uy, ux)`。若误用世界右法线 `(ux,−uy)`，会**镜像到反侧压住另一条线**。
  屏幕 y 向下、世界 y 向上，这是最容易搞反的一步。

**就近参考脚本**：`probe_start_label.py`（「标签放哪不被运动物体扫到」暴力搜索）、
`probe_s2_label.py` / `probe_s2_rule.py`（短矢量标签的逐角度间隙表 + 规则覆盖性检验）。
两者都是纯标准库、改改常量就能复用到新题。

### 附：单独输出「动画演示」单栏页（可选交付形态）

> 触发：用户在完整教学动画之外，明确要求「单独输出教学动画」「只要动画」「抽出动画部分」。
> 做法：**不要另写一份动画代码**，而是从已生成的完整 HTML **抽取同一份脚本与画布**，
> 只改骨架与布局——这样动画逻辑与完整版永远同源，不会产生两套会漂移的实现。

**脚本**：**首选 `_build/extract_anim_sensor.py`**（纯标准库；顶部 `SRC`/`OUT`/`CV_W` 常量按题改），
或各题专用脚本：`extract_anim_arc.py`（多了「不改 VIEW」「双 `<style>` 锚点」两处说明）、
`extract_anim_bike.py`（多了「让位判断必须删」的实证 + 探针剥离注释的处理）。
旧版 `_build/extract_anim_only.py` 只做了下面第 1~4 步，**用它会出现「首屏画布上半空白 / 圆波前变椭圆 / 悬浮着点了没反应的『知识点』按钮」三类缺陷**——新题直接拷 `extract_anim_sensor.py`。

**七个动作**（顺序不可颠倒，每步都有 `assert` 锚点唯一；漏一个就是肉眼可见的缺陷）：

1. **骨架**：定位 `<div class="wrap">`（用 `div` 标签配平定位闭合位置，不靠正则猜），
   在区间内只截取 `<section class="col col-animation"> … </section>`，其余两栏丢弃。
2. **画布定宽**：把 `canvas{width:100%…}` 改成 `width:680px;margin:0 auto`。
   **这一步是必须的**：原 `.wrap{display:flex}` 是三栏 `1 / 2 / 1.3` 的比例，
   只剩一栏时 `flex` 会把它拉满整页宽度，`resize()` 里的 `cv.clientWidth` 随之变大，
   画布被整体放大 → 字号与线宽相对变小、看上去「虚」。
   ⚠️ 单栏容器 `max-width` 要取 **`CV_W + 40`**：`.col` 有 12px padding + 1px border，
   取 `+24` 时内容盒只剩 678px，画布的 `max-width:100%` 会把它压窄、世界纵比校正随之失效。
3. **追加单栏布局**：`.wrap{flex-direction:column;align-items:center}` +
   `.col-animation{flex:0 0 auto;max-width:720px;position:static}`（`position:static` 是
   为了去掉原模板给动画栏设的 `position:sticky`，单栏下不需要悬停吸附）。
   注意 CSS 里的 `%` 在 Python 字符串格式化中要写成 `%%`，或用 `.replace()` 占位，否则报
   `unsupported format character`。
   ⚠️ **锚点不能直接用 `"</style>"`**：有的题页首有第二个 `<style id="tune-width">`（公式溢出微调块），
   `</style>` 会命中 2 次 ⇒ 改用 `"</style>\n</head>"`。追加的布局须排在最后才生效。
4. **关闭左/中栏渲染**：把 `renderProblem();`、`renderSteps();`、`renderInlineKnowledgeCards();`、
   `renderDrawer();`、`bindDrawer();` 这 5 条**独立成行**的调用注释掉，
   并删掉「renderProblem() 之后补画题图」的那句 `drawFigures();`。
   —— 动画所需的一切（`#cv`、控件、`panelData`、`stateAt/drawFrame/readouts`）全部保留，
   模板自身的 `if (!el) return` 防御足以兜住剩下的空引用。
5. **校正 `VIEW.ymax`——但只当原值是多宽度折中取的才改**：模板有 `*{box-sizing:border-box}`，
   `canvas{width:680px}` 的 **`clientWidth` 实为 678**（左右各 1px 边框被算进宽度），
   `resize()` 是按 `clientWidth` 算像素尺寸的，所以世界纵比必须按 **678** 而非 680 推算：
   `RATIO = (0.66×678 − 72) / (678 − 72) = 0.61960`，`yrange = xrange × RATIO`。
   自检：`xscale` 与 `yscale` 必须相等。
   注意 `ctx.arc(px,py,r*scale)` 画的圆不受影响，**只有用 `W2S` 逐点描出的圆弧（超声波波前、旋轮线）会被拉成椭圆**。
   **反例（安徽14 弧轨道题）**：其 `VIEW` 比值 0.6885 与 0.61960 差 11%，但完整版三栏下本就是这取值，
   单栏若独改，会让**同一道题的两个版本场景比例不一致**——比失真更糟。**这种情况沿用原值**，
   并在脚本里打印出该事实备查。判断准则：原值是否随视口宽度折中过（看注释/看是否等于某个整数近似）。
6. **去掉 HUD 的 `if (t > 0.002)` 让位判断**（若存在）：完整版把过程横幅 / 信息带 / 图例挡在首帧之外，
   是为了让左栏题图（= 动画第 0 帧的孪生重绘）与原题图完全一致；单栏版已无题图，
   保留这个判断会让**首屏只剩主体**（实测位移传感器题首帧非白像素 61,409 → 416,859；
   自行车题的位移箭头 / 过程横幅 / θ(t) 显示器 / 图例**全部缺失**，只剩一辆自行车）。
   注：并非每题都有这个显式判断——有的题靠 `if (Wp < 380) return;` 在窄画布上跳过 HUD，
   单栏画布 680px 会自动让 HUD 显示出来，此时**无需改动代码**，只需在审计里确认首帧 HUD 可见。
   ⚠️ **替换后探针别直接搜裸串 `if (t > 0.002)`**：替换文本里通常会写一句注释「原为 `if (t > 0.002){`」，
   裸串搜索会命中注释造成**假 FOUND**。正确做法：**先剥掉 JS 注释（块注释 + 行注释）再搜**。
7. **清掉已失效的交互入口**：`renderDrawer()/bindDrawer()` 一停用，`<button id="kpToggle">📚 知识点</button>`
   就成了「点了没反应」的死按钮，连 `<aside id="kpDrawer">` 整块一起删；同时把标题里的
   `· 分步解析与动画演示` 改成 `· 动画演示`（该页已无解析栏）。

**验证**：`_build/audit_anim_sensor.js` / `audit_anim_arc.js` / `audit_anim_bike.js`（门禁 + 四宽度），
以及 `_build/shot_zoom_ao.js` / `shot_zoom_arc_ao.js` / `shot_zoom_bike.js`
（按**画布坐标** 3× 裁剪任意区域，核对细线/叠字最省事的工具，
用法 `node shot_zoom_arc_ao.js <t分数> <out> [x0 y0 x1 y1]`）。

**单栏版必须在门禁里加的两条**（`audit_anim_bike.js` 的实现，值得照抄）：
- **首帧四要素分区非白像素**（banner / hud / legend / middle 各自 >0）——专防第 6 步没做到位；
- **`distinctFrames >= 5`**（在 6 个时间分数上取画布像素哈希，要求至少 5 个互不相同）——
  专防「第 6 步改错 ⇒ `loop()` 里 render 抛错、rAF 不再排期、动画冻在 t=0」。

⚠️ **模板级修复必须回填历史文件**：`assets/template.html` 修好之后，已产出的 HTML 里
**内联的旧副本仍是坏的**。`FIG.processBanner` 的 devicePixel 坑就是这样：模板修了，
但自行车题首屏横幅**整条不显示**（画到画布外）。改完模板务必跑
`_build/patch_processbanner.py` 扫一遍全部已产出 HTML（曾一次修好 7 个文件）。

> **⚠️ 交付前必须用 3× 特写人工看图（多时刻）——自动化门禁查不出下面这类缺陷。**
> 实例（安徽14 弧轨道题）：单栏版首屏横幅只露左半截、放大视图 HUD 整块消失，
> 而门禁的「画布非白像素 > 0 / 零报错 / 四宽度零溢出 / 公式零 error」**全部通过**。
> 根因见下方「画布尺寸必须取 CSS 像素」条——**dpr=1 时完全正常，只在高分屏上才暴露**。
关注点：`.col` 数量必须为 **1**；`getBoundingClientRect().width` 恒为 **680** 且 `clientWidth` 恒为 **678**；
画布比例 0.6603；**首帧（t=0）信息带区域非白像素 > 0**（第 6 步的专用门禁）；`panelData` 内的
`mjx-container` > 0 且零 `mjx-error`、面板文本无裸露 `$`；拖动时间轴后画面变化；「下一步/上一步」有效；
四宽度 `hOverflow = 0`；控制台零报错。

> ⚠️ **写单栏审计脚本时必踩的两个 Playwright 陷阱**（否则脚本会**静默挂死 10 分钟且零输出**，极易误判成页面故障）：
> 1. **`browser.close()` 在本模板页面上不返回**（常驻 `requestAnimationFrame` + MathJax，headless shell 会话关不干净）。
>    必须 `await Promise.race([browser.close().catch(()=>{}), 6 秒超时])` 后**显式 `process.exit(code)`**；
>    并把每个 `await` 都包一层超时（`T(promise, ms, tag)`）。定位手段：`_build/probe_anim_stage.js`
>    分段打印进度，卡在哪一步一目了然。
> 2. **`page.click()` 会长时间挂起**：Playwright 要等「元素稳定 + 可接收指针事件」，而本模板每帧重绘永远不满足。
>    控件校验改用 `page.evaluate(id => document.getElementById(id).click())`（等价于按，但不等可操作性）。
>    另外**输出要重定向到文件**（`> _build/_audit_x.txt 2>&1`），不要 `| head -N` ——管道下卡住时看不到卡住前的日志。
